# ديل لاين — المصدر المدموج

هذا المجلد يدمج حزمتين:

| الحزمة | ما فيها | أين صارت |
|---|---|---|
| `Deal-Line-Claude-Handoff.zip` | **ناتج بناء** موقع ديل لاين (Vinext/Workers)، وليس المصدر الأصلي، مع 15 وثيقة مشروع | `reference/` كما هي دون تعديل، ومصدر مستعاد في `web/src/app/` |
| `dealline-website-builder.zip` | خادم (Hono + Postgres): منشئ موقع المكتب، المخزون، العملاء، البيع على الخارطة، الأتمتة، التكاملات | `api/` |

## ما المستعاد وما لم يُستعد
- **مستعاد:** كود الصفحة من حزمة SSR الموجودة في البناء (`server/ssr/assets/page-*.js`). كانت غير مضغوطة، فحوّلتها أداة (Babel) من استدعاءات `jsx()` إلى JSX: `property-data`، `quality-ui`، `demo-domain`، `experience`، `page`. الأيقونات من `lucide-react@1.31.0` والخطوط من `@fontsource` بالإصدارات نفسها (بصمات ملفات الخطوط مطابقة للبناء الأصلي). React 19.2.6 كما في البناء.
- **لم يُستعد:** أنواع TypeScript (حذفها البناء؛ الملفات المستعادة `.jsx/.js`)، مصدر Tailwind (ملف CSS المبني مستخدم كما هو)، تاريخ Git، الاختبارات الأصلية، إعداد Vinext. التطبيق الأصلي صفحة واحدة `/` بمكوّن عميل واحد، فاستُبدلت Vinext بـ Vite + React مع سلوك مطابق.
- البوابات الست الأصلية (العميل، مبيعات العقار، المطور، موظف البنك، إدارة البنك، إدارة المنصة) **ما زالت بيانات توضيحية** كما كانت. لم أربطها بالخادم.

## ما الجديد بعد الدمج
في صفحة الدخول بطاقة جديدة: **«المكتب العقاري والمطور — متصل بالخادم»** (أو مباشرة `#/office`). كل ما فيها يُقرأ ويُكتب عبر الـ API الحقيقي:
- **لوحة اليوم:** عملاء جدد، مهام، مخزون، تحصيلات مشاريع الخارطة.
- **موقع المكتب:** الرابط، القالب، الألوان، الخط، الشعار، SEO، التواصل، رخصة فال، النشر، النطاق الخاص (سجلات DNS + التحقق)، العربون (متوقف).
- **العقارات الجاهزة:** إضافة، تعديل، نشر (يُرفض بدون رخصة إعلان سارية)، بيع، أرشفة، حذف.
- **العملاء المحتملون:** الحالة، الإسناد للفريق، المصدر (سناب، تيك توك، إكس…)، محادثة واتساب (قاعدة 24 ساعة).
- **مشاريع على الخارطة:** وافي، حساب الضمان، الوحدات (فردية أو دفعة)، خطط دفع مجموعها 100%، تقارير الإنجاز.
- **صفقات الخارطة:** حجز مؤقت ← إيداع في حساب الضمان ← تأكيد ← عقد ← تسليم، والتعثر والإلغاء والتنازل مع السبب.
- **الأتمتة والمهام:** قواعد «إذا… فـ…»، سجل التنفيذ، المهام.
- **التكاملات:** ربط واتساب، Webhooks موقعة، مفاتيح API.
- **الحساب والفريق.**
- **موقع المكتب العام** `#/site/<slug>`: ما يراه الزائر. العقارات والمشاريع ونموذج الاهتمام يدخل مباشرة في العملاء.

### تعديلات على الخادم
1. `GET /api/members`: قائمة الفريق لاختيار المسؤول، والبريد يظهر للمالك والمشرف فقط.
2. **إصلاح خلل:** وثائق الخادم تذكر `x` مصدرًا للعملاء، لكن الـ API وقيد قاعدة البيانات كانا يشترطان حرفين على الأقل، فكانت عملاء إكس تُرفض. أصلحته في الـ API وفي migration جديدة `004`، وتركت `003` دون تعديل.
3. `scripts/demo-seed.ts`: بيانات تجريبية (أسماء وأرقام مختلقة) تُدخل عبر الـ API نفسه.
4. `npm run dev:pglite` (الخادم بدون Postgres) و`npm run seed:demo` (البيانات التجريبية في Postgres).

## التشغيل

المتطلبات: Node 22. كل مجلد له `package-lock.json`.

**الطريقة الأسرع (بدون Postgres):** طرفيتان.
```bash
cd dealline/api && npm ci && npm run dev:pglite
```
```bash
cd dealline/web && npm ci && npm run dev
```
افتح `http://localhost:5173/#/office`. الدخول: `owner@dealline.test` أو `admin@dealline.test` أو `sales@dealline.test`، وكلمة المرور `demo-password-123`. البيانات تُحفظ في `api/.pglite`.

**مع Postgres حقيقي:** انسخ `api/.env.example` إلى `api/.env.local` واضبط `DATABASE_URL`، ثم:
```bash
cd dealline/api && npm run migrate && npm run seed:demo && npm run dev
```

**النسخة التجريبية داخل المتصفح** (الـ API نفسه يعمل على PGlite داخل التبويب، بلا خادم):
```bash
cd dealline/web && npm run build:demo && npm run preview:demo
```

الاختبارات:
```bash
cd dealline/api && npm test && npm run typecheck
```

### ما لم أختبره أو ما زال تجريبيًا
- البريد (Resend)، واتساب (Meta)، الدفع (ميسّر): لم تُختبر مع الخدمات الحقيقية لعدم وجود حسابات، والاختبارات تستخدم بدائل مزيفة.
- التحقق من النطاق الخاص وفحص عناوين Webhook (SSRF) يحتاجان DNS من الخادم، فلا يعملان في النسخة داخل المتصفح (يُرفضان بأمان).
- قيم القالب الثلاث (classic/modern/minimal) تُحفظ، لكن الموقع العام يعرض تخطيطًا واحدًا.
- رفع الصور ودعوة أعضاء الفريق بالبريد لم يُبنيا في الخادم بعد.
- الاستضافات المُدارة (Supabase، Neon) لم تُجرّب. الـ migration تنشئ دورًا (`create role`)، فيلزم أن يملك مستخدم قاعدة البيانات صلاحية CREATEROLE.
- النسخة داخل المتصفح: إذا فُتحت في تبويبين، يحفظ تبويب واحد فقط (قفل Web Locks) والآخر يعمل على نسخة مؤقتة.
- لم أعدّل النشر ولم أستخدم `reference/build/dist/.openai` (هوية الاستضافة) كما طلبت التعليمات.

### علاقة الدمج بسجل القرارات
- يحترم: DEC-005/006 (حجز نشط واحد لكل وحدة، بقيد فريد)، DEC-007 (الجاهز منفصل عن الخارطة)، DEC-008 (حساب الضمان يُتابع ولا يُمسك)، DEC-022 (منع التكرار)، DEC-028 (عزل الجهات).
- **OPEN-004 (دفعة حجز أم حجز مؤقت):** حزمة الخادم فيها عربون عبر ميسّر للعقارات الجاهزة. تركته **متوقفًا**، ولا يعمل بدون مفاتيح ميسّر. القرار ما زال مفتوحًا ويحتاج مراجعة نظامية.
- **OPEN-005 (مدة الحجز):** الخادم يجعلها إعدادًا لكل مشروع (افتراضي 3 أيام)، وهذا افتراض وليس قرارًا.
- **DEC-041 (التدخل اليدوي):** استثناءات الصفقة تُسجل الفاعل والسبب والوقت، لكن «الحالة قبل/بعد» لا تُخزن صراحة، وتغييرات العقارات والإسناد بلا سجل تدقيق. هذه فجوة.
- لم أغيّر أي قرار مؤكد.

### نسخة المعاينة المنشورة
في نسخة المعاينة (`build:demo`) استبدلت أسماء البنوك الحقيقية التي يذكرها العرض الأصلي (مع عروض ونسب مختلقة) بأسماء محايدة («مصرف تجريبي (أ)»…)، حتى لا تُنسب عروض غير حقيقية لبنوك حقيقية. المصدر المستعاد بقي كما وُجد.
