# تعليمات تسليم إلى Claude

أريد تطوير موقع ديل لاين الموجود في هذه الحزمة. ابدأ بقراءة README_AR.md وأخبرني أن الملفات ناتج بناء وليست المصدر الأصلي. لا تدّعِ أنها مشروع جاهز بأوامر npm غير موجودة.

1. اقرأ Master Context وDecision Registry داخل project-context قبل أي تغيير جوهري. احفظ القرارات CONFIRMED؛ ميّز ASSUMPTION وREGULATORY-GATE. عند تغيير قرار، احتفظ بتاريخ القديم بوصفه DEPRECATED.
2. الاسم الحالي ديل لاين. الصورة المرجعية لتوجيه التصميم، وليست بديلًا عن سلوك البوابات.
3. افحص build/dist/client/assets وbuild/dist/server لاستنتاج السلوك الموجود. لا تعتبر كل واجهة تكاملًا فعليًا.
4. إن لم يتوفر المستودع الأصلي، أنشئ مشروع مصدر جديدًا قابلًا للصيانة، وافصل المكونات والبيانات والتنسيق، مع بيان السلوك المستعاد وما لم تستطع استعادته. لا تمسح هذه النسخة المرجعية.
5. حافظ على العربية وRTL والجوال وإمكانية الوصول، وحركات هادئة تحترم prefers-reduced-motion. استخدم الصور والخطوط المرفقة.
6. لا تفعّل تمويلًا أو دفعًا أو نفاذًا أو حجوزات مالية على أساس بيانات العرض؛ تحقق من المتطلبات الرسمية عند تغيير نطاق تنظيمي.
7. اختبر كل بوابة وتدفقات الطلبات والصلاحيات والمخرجات وحالات الفراغ والخطأ واستمرار البيانات. بيّن بدقة ما اختبرته وما بقي تجريبيًا.
8. لا تعِد النشر إلى هوية الموقع الموجودة في إعداد الاستضافة دون طلب واضح.

بعد فحصك للحزمة، طبّق التحديثات التي سأرسلها، وقدّم ملفات المصدر الكاملة وأوامر التشغيل الفعلية مع ملف القفل وتقرير تحقق.
